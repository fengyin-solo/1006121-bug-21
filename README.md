# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 应急演练整改：一次落到底

- **单一数据源**：演练整改措施、演练进度（已整改）、参演班组名单与安全巡检「整改问题清单」
  在 `commit()` 的同一次原子写入里落库；任一项写不齐全笔退回，内存与存储都不留半条记录。
  巡检问题按 `来源单号 = 演练编号` 去重，演练页与巡检页读的是同一份，两侧只留一条。
- **整改日期只认第一次**：重复提交（含重复点两次）沿用头一次的整改日期与整改单号，
  已完成整改的演练不能再次登记整改。整改期限统一算法：**整改日期 + 7 个自然日**，
  以安全巡检整改问题清单那份为准，演练页同源展示。
- **中断续办**：提交先入与业务记录同库的续办队列（每条演练只占一格），再逐条原子落库；
  入库失败整笔不落、断点保留，重新进入（App 挂载或页面 `onMounted`）从最早断掉那条接着走。
- **读写同源**：读取只认磁盘落库那份（`localStorage` 读失败重试 3 次，损坏时抛错而不是
  用示例数据顶回来）；`storage` 事件让多标签页/其他入口同步看到同一份。
- **越权与越级**：顶栏可切换「演练组织人 / 安全员 / 参演班组 / 值班管理员」角色。
  演练动作限组织人（管理员可兜底），巡检派发/闭环限安全员；状态只能在相邻环节流转，
  已整改演练的演练科目锁定不可改。拦截结果带 `blockedAt`，明确说明卡在哪一环。
- **存量补录**：v1 数据首次读取时自动迁移到 v2，已是「已整改」的存量演练按演练日期补
  整改日期、期限与单号，并在巡检清单补一条「已闭环」的历史问题，不进待整改数。

数据层不变量可用 `cd frontend && npm run verify` 回归（共 41 项断言）。
